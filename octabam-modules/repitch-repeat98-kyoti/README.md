# REPITCH_REPEAT98_KYOTI

Tempo-locked varispeed for STATIC and FLEX tracks, as three extra TSTR positions after the
four stock ones:

| TSTR | what it does |
|---|---|
| **RPCH** | follows the project tempo by playback speed, without grains (the basic Repitch) |
| **RPS9** | the same, with an S900/S950-style repitch emulation |
| **RPSP** | the same, with an SP-1200-style repitch emulation (its raw outputs 7/8) |

On a repitch track the PTCH knob becomes **QUAN**: one detent per ratio.

**Credit:** Jannik Aßfalg ([repeat98](https://github.com/repeat98)) wrote the basic Repitch
(octabam's `modules/repitch`). Zac Kyoti wrote the S900/S950 and SP-1200 repitch emulations
and the Quantizer.

**Hardware-confirmed in this octabam form** (the author's MKI, 2026-10-05 to 10-08; see Measured).
Needs octabam with #573 (XY dual moves with an ALU op) and #603 (`ptable2`, tables in a
given-up effect's X data).

## Contents

| file | what it is |
|---|---|
| `manifest.py` | the octabam module declaration: three DRAM units, 14 `jmp` detours, 7 symbol refs, 5 pokes, two DSP hooks |
| `patch_repitch_kyoti.s` | the ColdFire logic (unit `rpk_logic`) |
| `rpk_glyphs.s` | the seven TSTR position glyphs (unit `rpk_glyphs`) |
| `patch_repitch_reload.s` | stock RELOAD PART treated as a Part apply (unit `rpk_reload`) |
| `rpk_dsp.asm` | the RPS9 / RPSP kernel (generated by `tools/repitch_dsp_octabam.py`) |
| `rpk_dsp_ptable.py` | its table words, two blocks of 81 and 384 (generated with it) |

Standalone image: `tools/build_repitch_repeat98_kyoti.py`.

## How it works

The detours are Jannik's seven (rate gate, pitch gate, rate hook, TSTR resolve, three
audio-editor ATTR hooks), the four page-1 dial renderers (the QUAN widget), the two Part
applies, and stock RELOAD PART. TSTR's count goes from 4 to 7 on the STATIC and FLEX
descriptors, with this module's formatter. PTCH gets the QUAN widget and encoder step.

**The 7-position selector.** Stock 1.40C has a 5-position select widget at `0x40046ab4`
that nothing in stock references: no pointer, no `jsr`, no PC-relative call. Jannik's
REPITCH uses it unmodified. This module patches it in place: its bound `moveq #4` becomes
`#6`, and its icon-table operand points at this module's glyphs. TSTR then points at it.
The standalone builder makes the same two changes to a copy in its cave; here no stock
byte is copied.

**Not with octabam's `REPITCH`.** Both grow the same Repitch: the same detour sites and
TSTR words. The module declares the conflict, and the ledger refuses the pair.

**The DSP kernel.** Two hooks. `zqrp`, at the voice kernel's prologue (payload A `P:0x40b`,
B `P:0x20e`): RPS9 and RPSP render the pass there; RPCH leaves it to stock's kernel.
`zqboot`, at each payload's one-time memory clear (`do b,LA`, A `P:0x46` / B `P:0x47`): it
runs the clear and copies the tables into Y at boot, outside every audio pass. The two
payloads' `do` words differ (their own LA), so the hook declares its stock words per payload.
RPSP (rev 17) renders the mid (L + R)/2 through the SP-1200 path and reads the side
(L - R)/2 clean, delayed to match; the output is raw, as the SP's outputs 7/8.
`rpk_dsp.asm` is the hardware-tested kernel (`tools/patch_repitch_dsp.asm`), generated into
octabam's form:
- its constants are written out
- its tables are two blocks, `ptable` (81 words: the render's half-table) and
  `ptable2` (384: the RPSP and RPS9 half-rows), read through `p:(rN)` by the boot copy only; octabam puts each in
  the curve bank, in P below the code, or in a given-up effect's own X data, and rewrites the
  reads to `x:(rN)` for X
- the table tag in Y is checked at every pass; if anything ever overwrote the copy, the
  next pass rebuilds it from the blocks

With only SPRING REV given up, as in the standalone, the code takes SPRING's P run and both
blocks SPRING's X data (octabam #603). It claims core-private `Y:$A00–$FFF`.

**In DRAM.** About 2.6 KB, more than octabam's floating ROM run has left beside the other
KYOTI modules. A remix with this module carries the platform loader and its 10 MiB reserve
unless another DRAM module already does.

## Measured

Hardware-confirmed on the author's MKI: the standalone image (rev 16) and the KYOTI V1.0
combined image. `rpk_logic` and `rpk_glyphs`, linked at the standalone image's own
addresses, are byte for byte that image, for `-mcpu=5407` and `54455` alike. Built by
octabam (`make bus`, a stock-effects remix with this module): it changes every stock site
the standalone image changes on the ColdFire side, and passes `verify_dram_boot`.

The DSP kernel (`tools/repitch_dsp_octabam_check.py`): run inside the stock voice module on
both payloads, in all three places octabam can put its two table blocks (P below the code,
the stock curve bank, and SPRING REVERB's own X data), it is bit-exact with the reference
model's DSP twin in all 264 cases, mode switches included. Rev 17: RPS9 52.2 and RPSP 112.8
instructions per sample (57 and 146 modelled cycles; rev 16: 61.6 and 171.8–174.0).
`tools/repitch_dsp_boot_check.py` boots both payloads with the boot hook: memory outside
`Y:$A00–$FFF` and the registers end as without it, and the tables equal the model's. In octabam, with
only SPRING REV given up, the placed code (SPRING's P run) and both blocks (SPRING's X data)
are word for word that build.

**On hardware, this octabam form:** the author's MKI, 2026-10-05, in an octabam-built image with all the KYOTI modules, REC_TRIG_MUTE and SIDECHAIN_COMPRESSOR, only SPRING REV given up (OBKYOTI11): RPCH follows the project tempo and PTCH reads QUAN, one ratio per detent; RPS9 and RPSP at several tempos, no clicks at trig starts; RPS9/RPSP on T5-T8 while a SIDECHAIN compressor ducks on that core; TSTR restored by a Part reload ([BANK]+[TRACK n] and stock RELOAD PART); DARK REV, DJ EQ and the other modules unaffected.

**Rev 17 on hardware** (2026-10-06 to 10-08, the same set, OBKYOTI13–16): RPSP on all four
tracks of one core with DARK REV on each runs clean on both cores. Adding DJ EQ on FX1 track
by track, T1–T4 pass four and T5–T8 three; a fourth on T5–T8 overloads the DSP (a loud
tone, the sequencer stops). Those images had an output filter on the SP mid; this build is
the same kernel without it (raw outputs 7/8), cheaper by about 21 modelled cycles a voice,
and has not itself been flashed yet.
